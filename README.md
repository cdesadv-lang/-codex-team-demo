# فريق Codex — تطبيق مهام متكامل

مشروع محلي حقيقي: React + TypeScript + Vite، خادم Node.js 24، وقاعدة SQLite دائمة. يدعم إضافة المهام وإكمالها وحذفها، بواجهة عربية RTL. لا يستخدم خدمات خارجية عند تشغيل التطبيق.

## التشغيل

يتطلب Node.js 24 وnpm وPython 3.11+ لفحص إعدادات الوكلاء.

```sh
cd /workspace/team-demo
npm --prefix web ci
npm run check:agents
npm test
npm run build
npm start
```

افتح http://127.0.0.1:3000 . تُنشأ قاعدة البيانات في `data/tasks.sqlite`. يمكن تخصيص `PORT` و`DB_PATH`. لتطوير الواجهة: شغّل الخادم ثم `npm --prefix web run dev` في نافذة أخرى؛ يمرر Vite طلبات API للخادم.

## إعداد الفريق

تعريفات الأدوار في `.codex/agents/*.toml`، وربطها في `.codex/config.toml`. اقرأ `AGENTS.md` لملكية الملفات والمراجعات والاختبارات والموافقات. لا يوجد تثبيت وهمي للوكلاء: التعريفات طبقات إعداد Codex وليست عمليات تعمل طوال الوقت.

ابدأ Codex من جذر المشروع: `codex -C /workspace/team-demo`. في تثبيت جديد قد يتجاهل Codex إعدادات المشاريع غير الموثوقة؛ راجع تنبيه الثقة في واجهته واعتمد المشروع الموثوق محليًا. لم نعدّل إعدادات حسابك أو الثقة العامة تلقائيًا. لاستخدام التعريفات في جلسة جديدة، اطلب من القائد تفويض العمل إلى `frontend_engineer`, `backend_engineer`, `qa_engineer`, `security_engineer` بأدوارها المسجلة. الجلسة الحالية تستخدم أداة تفويض مستضافة بأسماء المهام وتعليمات التخصص؛ لا تعيد تحميل ملفات الأدوار تلقائيًا.

مثال طلب: «نفّذ ميزة جديدة: عرّف عقد API أولًا، ثم فوّض ملفات web إلى frontend_engineer وserver إلى backend_engineer وtests إلى qa_engineer، واطلب مراجعة security_engineer. لا تعدّل ملفًا من وكيلين في الوقت نفسه، وشغّل الاختبارات والبناء قبل التسليم».

يفحص `check:agents` صيغة TOML ويطلب من محلل Codex المثبت قراءة إعداد التنسيق وكل ملف دور في بيئة إعداد مؤقتة، دون استدعاء نموذج أو تغيير إعدادات المستخدم. هذا التحقق مختلف عن إثبات تشغيل نموذج عبر CLI مستقل، الذي يتطلب وصولًا ومصادقة متاحة. راجع `docs/verification.md` لنتائج هذه الجلسة.

## الحدود الأمنية

للتجربة المحلية فقط؛ لا توجد حسابات أو مصادقة أو صلاحيات أو عزل مستأجرين. لا تنشره على الإنترنت بهذا الشكل. راجع `docs/security-review.md` لمتطلبات الانتقال إلى الإنتاج. SQLite في Node 24 قد يصدر تحذيرًا تجريبيًا. يلزم التحقق من الإتاحة والمتصفح والأداء قبل إصدار إنتاجي. لا نشر ولا استخدام خدمات مدفوعة دون موافقتك.

## فحص المتصفح الاختياري

توفّر هذه البيئة Chromium في `/usr/bin/chromium`. لا يضيف فحص المتصفح خدمة مدفوعة. لتثبيت المشغل مؤقتًا وتشغيل الفحص:

```sh
npm install --prefix /tmp/team-browser --cache /tmp/team-npm-cache --no-audit --no-fund --ignore-scripts playwright-core
PLAYWRIGHT_MODULE=/tmp/team-browser/node_modules/playwright-core/index.mjs node scripts/browser-smoke.mjs
```

يمكن تحديد `CHROMIUM_PATH` لمسار المتصفح. عند منع الكتابة إلى cache الافتراضي، استخدم `npm --prefix web ci --cache /tmp/team-npm-cache`. داخل بيئة Codex المقيدة تحتاج أوامر التثبيت واختبارات HTTP والمتصفح إلى صلاحية الشبكة الإضافية؛ لا تعطل العزل أو TLS.

## أدوار الإدارة والمنتج

أُضيف `agent_manager` لتخطيط التسليم وتوزيع ملكية الملفات ومتابعة الاختبارات والعوائق، و`agent_ceo` لتحديد الأولويات ومعايير النجاح وتوصيات القبول. أصبح الفريق ستة أدوار، مع حد سبع جلسات يشمل القائد، وعمق تفويض واحد. يمر طلب توزيع المهام من المدير إلى القائد لتفادي التفويض المتداخل.

مسار العمل: المستخدم ← توصيات CEO للنطاق ← خطة Manager ← تفويض القائد للمهندسين ← QA والأمن ← تجميع الأدلة ← توصية القبول. يظل قرار النشر والدفع للمستخدم وحده. ملفات الأدوار إعدادات لجلسات لاحقة؛ إضافتها لا تعني تشغيلها تلقائيًا في الجلسة الحالية.

## Senior UX/UI Engineer

أُضيف الدور `senior_ux_ui_engineer` لتصميم رحلات المستخدم، بنية المعلومات، التفاعلات، نظام التصميم، الإتاحة والواجهات العربية RTL. يملك مستندات `docs/ux/**` و`docs/design-system/**` عند التكليف، ويسلّم مواصفات قابلة للتنفيذ إلى مهندس الواجهة. تعديل ملفات `web/**` يتطلب نقل ملكية صريحًا قبل العمل لمنع التعارض.

أصبح الفريق سبعة أدوار متخصصة بالإضافة إلى القائد. يبقى حد التزامن سبع جلسات في هذه البيئة؛ لذلك يُشغّل القائد ستة وكلاء كحد أقصى بالتزامن ويجدول الدور المتبقي. إضافة التعريف لا تعني تشغيل الدور تلقائيًا.

## معاينة Render المحمية

إعداد `render.yaml` يجهز خدمة Node مجانية مؤقتة مع كلمة مرور واسم نطاق مسموح محدد. راجع [تعليمات المعاينة](docs/render-preview.md) قبل أي نشر. التشغيل المحلي العادي لا يتغير. هذا الإعداد لم يُنشر بعد، ويتطلب ربط حساب Render والتحقق من الحصة المجانية. لا تستخدمه لحفظ بيانات مهمة لأن تخزين SQLite مؤقت عند الاستضافة المجانية.

لفحص المتصفح بوضع كلمة المرور محليًا: أضف `SMOKE_PREVIEW=true` إلى أمر فحص Chromium السابق.
