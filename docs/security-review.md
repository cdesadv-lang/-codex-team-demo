# المراجعة الأمنية — 2026-10-16

## النطاق والنتيجة
راجعت فعليًا `server/app.js` و`server/main.js` و`web/src/main.tsx` و`web/index.html` و`AGENTS.md` و`.codex/config.toml` وتعريف الدور الأمني و`.gitignore`. التطبيق تجربة محلية أحادية قاعدة البيانات؛ ليس جاهزًا للإنتاج. هذه مراجعة للكود وليست اختبار اختراق أو شهادة خلو من الثغرات. نتائج اختبارات HTTP والبناء المرجع المعتمد لها تقرير QA وتشغيل القائد؛ لا أدّعي تشغيلها هنا.

## نموذج التهديد
الأصول: عناوين المهام وحالاتها وملف SQLite. الحدود: متصفح ← HTTP محلي ← الخادم ← قاعدة البيانات/ملفات الواجهة. مصدر الخطر موقع خارجي يحاول الوصول للخدمة المحلية، ومدخلات HTTP غير موثوقة، ومستخدم محلي يملك الوصول للخدمة أو الملفات. التطبيق لا ينفذ مصادقة أو صلاحيات أو عزل مؤسسات؛ يستطيع أي عميل محلي قادر على الاتصال قراءة جميع المهام وتعديلها وحذفها. لا تستخدم بيانات حساسة أو تعرض الخدمة للشبكة.

## الملاحظات والإجراءات
- **متوسطة، أُصلحت أثناء المراجعة: DNS rebinding.** كان التحقق من Origin يقارنه فقط بـHost، مما يتيح اسم نطاق مهاجم يشير إلى loopback. أبلغت مهندس الخلفية؛ أضاف قائمة Host محصورة في `localhost` و`127.0.0.1` و`[::1]` مع منفذ اختياري قبل معالجة المسارات. أعدت قراءة الإصلاح. يجب أن يظل رفض Host غير المسموح اختبار انحدار في QA.
- **عالٍ عند النشر، قيد مقصود للتجربة:** غياب الهوية والصلاحيات وعزل المستخدمين. ربط `127.0.0.1` وقائمة Host يقللان التعرض، لكنهما ليسا مصادقة. يلزم تصميم وتنفيذ تحقق هوية وصلاحيات على كل عملية وعزل مستأجرين قبل استخدام متعدد المستخدمين.
- **قبل الإنتاج:** لا توجد حدود عدد/حجم إجمالي للمهام أو pagination أو ضبط معدل طلبات؛ يمكن لعميل محلي استهلاك القرص/الذاكرة. يلزم quotas وpagination ومراقبة وحدود موارد مناسبة.
- **قبل الإنتاج:** قاعدة SQLite غير مشفرة على مستوى التطبيق؛ صلاحيات الملف تعتمد على حساب التشغيل وumask. يلزم حساب خدمة محدود، أذونات صريحة، نسخ احتياطي واستعادة مجربان، وسياسة احتفاظ وحذف وتشفير ملائم للبيانات.
- **تحقق متبقٍ:** يجب تدقيق الاعتماديات الفعلية والـlockfile باستخدام مصدر ثغرات حديث قبل إطلاق منتج. مراجعة كود React لا تثبت سلامة جميع اعتمادياته. لا أدعي نجاح audit لم يُشغّل.

## الضوابط المرصودة في الكود
- ربط الخادم الافتراضي بـ`127.0.0.1`، والتحقق من المنفذ، ورفض Host غير المحلي.
- عمليات كتابة API ترفض Origin مختلفًا متى أرسله العميل؛ إنشاء/تحديث يتطلب JSON، لذلك نموذج HTML العادي لا يكتب. لا توجد ترويسات CORS تتيح القراءة عبر أصل آخر. حذف المهام يتطلب DELETE. الطلبات بلا Origin مسموحة لعملاء محليين؛ ليست آلية صلاحيات.
- حد جسم JSON هو 4096 بايت؛ رفض JSON غير صالح، مفاتيح غير متوقعة، عناوين فارغة/أطول من 200، completed غير منطقي، ومعرفات غير آمنة.
- جميع قيم SQL تمر عبر prepared statements ومعاملات، مع CHECK constraints في SQLite.
- تقديم الملفات يستخدم realpath ويتحقق من بقاء الملف داخل جذر الواجهة، ويرفض NUL وbackslash. لا يقدم مجلد قاعدة البيانات.
- React يعرض عنوان المهمة كنص مهرب؛ لا يوجد dangerouslySetInnerHTML في التنفيذ المراجع. تُستخدم أصول محلية.
- CSP يحصر السكربتات والأنماط والاتصالات في نفس الأصل، مع frame-ancestors none، وnosniff وDENY وno-referrer وno-store. HTTPS/HSTS من متطلبات النشر بعد الموافقة وليسا مطبقين في الخادم المحلي.
- أخطاء الخادم غير المتوقعة لا تُرجع stack trace للعميل.

## حوكمة الوكلاء والأسرار
`AGENTS.md` يحدد ملكية ملفات مستقلة ومراجعة ونتائج اختبارات صريحة؛ يتطلب موافقة المستخدم للنشر والخدمات المدفوعة والتغييرات المدمرة والتعرض العام. إعداد Codex يستخدم workspace-write وon-request ولا يعطّل الموافقات. تعريف الدور الأمني يكرر الحظر وملكية ملف المراجعة. `.gitignore` يستبعد ملفات البيئة وقاعدة البيانات وnode_modules. لم أقرأ مجلدات الاعتماديات السرية في البيئة، ولم أنشر أو أستخدم خدمات مدفوعة.

الموافقات التقنية في Codex ليست بديلًا عن سياسة المشروع: يجب أن يطلب القائد موافقة صريحة قبل أي نشر حتى إن لم تعرض الأداة نافذة موافقة.

## مراجعة المعاينة المؤقتة — 2026-10-16
راجعت الكود الحالي في `server/app.js` و`server/main.js` وإعداد `render.yaml` ودليل `docs/render-preview.md` قراءةً فقط؛ لم أنشر الخدمة، ولم أشغّل اختبارات في هذه المراجعة. لم أجد عيبًا مانعًا في نطاق حماية المعاينة المذكور، وهذه ليست موافقة على جاهزية إنتاجية.

- التشغيل الافتراضي يستمع على loopback. وضع المعاينة وحده يفتح `0.0.0.0` بعد اشتراط كلمة مرور بطول 24 حرفًا على الأقل واسم DNS صالح. يفشل بدء التشغيل عند غياب أي منهما أو عند قيمة PREVIEW_MODE غير صالحة.
- Basic Auth باسم `preview` يحمي ملفات الواجهة وAPI والمسارات الأخرى؛ الاستثناء المقصود فقط GET/HEAD على `/healthz` ويعيد حالة ثابتة بلا مهام. المقارنة تستخدم digest ثابت الطول وtimingSafeEqual، والأخطاء لا تكشف كلمة المرور.
- قائمة Host تقبل أسماء loopback واسم الاستضافة المحدد بالضبط، دون wildcard؛ لا يستخدم الكود X-Forwarded-Host لاتخاذ قرار السماح. تحقق Origin لكتابات API واشتراط JSON للإنشاء والتحديث باقٍ، ولا توجد CORS مفتوحة.
- ملف Render يطلب خطة free وخدمة واحدة دون قرص دائم، ويولد السر في إعداد المنصة عبر generateValue؛ لم أجد قيمة اعتماد مضمنة في الملفات المراجعة. التحقق من الخطة الفعلية وحدود الحساب قبل الإنشاء ما زال مطلوبًا.
- المتبقي: HTTPS يعتمد على إنهاء TLS لدى Render؛ Basic Auth مشترك، بلا هوية فردية أو عزل أو إلغاء جلسة مستقل أو rate limiting. لا تستخدم بيانات حساسة؛ SQLite مؤقتة وبياناتها عرضة للفقد. عنوان الإنترنت محمي بكلمة مرور لكنه ليس شبكة خاصة. يجب إيقاف المعاينة بعد التجربة، ولا يُفترض انتهاء تلقائي لها.
